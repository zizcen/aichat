# 模型能力映射

旧版公共 `GET /v1/models` 只返回 `id/object/created/owned_by`，不会暴露管理端的 provider/capability。因此客户端按以下优先级选择工作区：

1. 读取服务端以后可能增加的 `capability`、`capabilities` 或 `supports` 字段。
2. 对已知模型名做保守 fallback：包含 `image/imagine` 的模型视为图片，包含 `video` 的模型视为视频，包含 `voice/tts` 的模型视为 TTS，包含 `stt/transcri/whisper` 的模型视为 STT，其余普通模型视为聊天。
3. 未知模型不自动宣称媒体能力，工作区保留手动模型 ID 输入。

当前 fallback 只影响 UI 默认选择，不绕过服务端 Key 白名单。真实部署联调时，应把 `/v1/models` 脱敏响应和实际可用 endpoint 记录到接口适配报告中；若服务端增加 capability 字段，保留旧字段即可向后兼容。

## 公共媒体地址

图片和视频响应中的归档地址应来自 `frontend.publicApiBaseURL`（或管理端运行设置中的 Public API Base URL），填写用户可访问的 HTTPS 网关根地址，不要包含 `/v1`。若旧版部署未配置该值，服务端可能返回 `http://127.0.0.1:8000/v1/media/...`；客户端会将明确属于 `/v1/media/images|videos/` 的内部地址改写到用户当前 Base URL。任意其他文件 URL 不会被自动改写或放行。
