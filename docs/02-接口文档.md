# 公共接口适配文档

本版按 `v3.1.4` 源码复核，路由注册位于 `backend/internal/transport/http/inference/handler.go:85-109`，公开归档媒体位于 `backend/internal/transport/http/media/handler.go:26-45`，创作台请求构造位于 `frontend/src/features/creative-console/creative-console-api.ts`。如果 VPS 不是该版本，开发者必须先用真实部署重新跑一遍接口探测。

## 1. 通用约定

Base URL 由用户输入，例如 `https://grok.example.com`。客户端统一去掉末尾 `/`，公共接口前缀为 `{baseUrl}/v1`。

除健康检查外，公共接口使用：

```http
Authorization: Bearer g2a_xxx_xxx
Accept: application/json
```

服务端同时接受 `X-API-Key: g2a_xxx_xxx`，但 APK 统一使用 Authorization，避免不同协议分支。JSON 请求增加 `Content-Type: application/json`。错误通常为：

```json
{"error":{"message":"human readable message","type":"invalid_request_error","code":"some_code","param":null}}
```

客户端必须保留 HTTP 状态码和 `error.code`，不要只显示“请求失败”。

## 2. 连接与模型

### `GET /healthz`

无需 Key。200 表示进程存活。用于判断 URL 和网络基本可达。

### `GET /readyz`

无需 Key。200 表示就绪；503 表示服务尚未准备好。

### `GET /v1/models`

需要 Bearer Key。200 响应示例：

```json
{
  "object":"list",
  "data":[
    {"id":"grok-4.5","object":"model","created":0,"owned_by":"gateway"}
  ]
}
```

Client Key 的模型白名单会在服务端过滤结果；空列表不能视为网络错误，应提示 Key 没有可用模型。当前响应不包含 `capability/provider`；`created` 是 Unix 秒，`owned_by` 由服务端决定。见产品文档第 4 节。

## 3. 聊天 Responses（推荐）

### `POST /v1/responses`

聊天推荐使用 Responses，因为创作台当前直接消费该协议的 SSE。

```json
{
  "model":"grok-4.5",
  "input":[
    {"role":"user","content":"你好"}
  ],
  "stream":true,
  "store":false,
  "prompt_cache_key":"local-session-uuid",
  "reasoning":{"summary":"auto"},
  "tools":[{"type":"web_search"}]
}
```

字段规则：`model` 必填；`input` 为消息数组；MVP 固定 `store:false`；`prompt_cache_key` 可选且不得包含 API Key；`reasoning` 可使用 `{"effort":"none"}` 或 `{"effort":"low|medium|high|xhigh","summary":"auto"}`；`tools` 可选，只有用户打开联网搜索且服务端支持时发送。

服务端会原样接收并转换请求体中的 `input`、`tools` 等字段，另支持可选 `previous_response_id`。客户端不要把请求体压缩成只含 `model` 的最小 DTO，否则多轮或工具参数可能丢失。

`stream:true` 期望 `Content-Type: text/event-stream`。客户端按空行拆事件，拼接每个 `data:` 行；识别以下事件：

- `response.output_text.delta` / `.done`
- `response.reasoning_summary_text.delta` / `.done`
- `response.reasoning_text.delta` / `.done`
- `response.output_item.added` / `.done`
- `response.function_call_arguments.delta` / `.done`
- `response.custom_tool_call_input.delta` / `.done`
- `response.completed`、`response.incomplete`、`response.failed`、`error`

非 SSE 的 200 JSON 也应兼容，读取响应中的文本、推理和工具信息。收到 `response.incomplete/failed/error` 时保留已有部分内容并显示错误。用户停止或页面离开必须取消 HTTP 流。

### `GET/DELETE /v1/responses/{response_id}`

P1。用于服务端存储响应的读取和删除；MVP 本地会话不依赖该接口。

### `POST /v1/responses/compact`

P2。用于服务端压缩支持的 Response 会话；MVP 可只做本地消息截断确认。

## 4. Chat Completions（兼容接口）

### `POST /v1/chat/completions`

P1 或兼容模式使用。请求示例：

```json
{
  "model":"grok-chat-fast",
  "messages":[{"role":"user","content":"你好"}],
  "stream":true
}
```

响应可为 JSON 或 SSE；支持图片输入和函数工具。除非目标部署的 Responses 能力不可用，不建议 MVP 同时维护两套聊天解析器。

### `POST /v1/messages`（P2）

Anthropic 兼容接口。除 Bearer Key 外，必须带 `anthropic-version: 2023-06-01`；请求至少需要 `model`、正整数 `max_tokens` 和非空 `messages`，`stream` 可选。该接口的错误包与 OpenAI 接口不同，形如 `{"type":"error","error":{"type":"authentication_error","message":"..."}}`。MVP 不实现，除非后续需要兼容 Claude 客户端。

## 5. 图片

### `POST /v1/images/generations`

```json
{
  "model":"grok-imagine-image",
  "prompt":"一座雨夜城市",
  "n":1,
  "aspect_ratio":"16:9",
  "resolution":"1k",
  "response_format":"url",
  "stream":false
}
```

服务端允许 `n` 为 1–10，当前创作台 UI 只提供 1–4。支持的 `aspect_ratio` 包括 `auto`、`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`2:1`、`1:2`、`19.5:9`、`9:19.5`、`20:9`、`9:20`；APK 可先暴露 UI 已验证的子集。可选 `quality:"low"|"medium"`。响应为 `{created,data:[...]}`，每项可能含 `url`、`b64_json` 或 `revised_prompt`。客户端两者都必须支持；相对 `/v1/media/images/{asset_id}` URL 要拼接用户 Base URL，外部 HTTPS URL 原样保留。

### `POST /v1/images/edits`（P1）

```json
{
  "model":"grok-imagine-image-edit",
  "prompt":"把背景改成黑色",
  "image":{"url":"https://example.com/source.png"},
  "n":1,
  "aspect_ratio":"1:1",
  "resolution":"1k",
  "response_format":"url",
  "stream":false
}
```

服务端也接受 `images` 数组（1–8 项），但每一项当前必须是 `url`，`file_id` 会被拒绝；`n` 为 1–10，`resolution` 为 `1k|2k`。MVP 不假设客户端可直接上传文件；公网 URL 是最小兼容输入。

## 6. 视频异步任务

### `POST /v1/videos/generations`

```json
{
  "model":"grok-imagine-video",
  "prompt":"雨中城市的电影感跟拍",
  "duration":8,
  "aspect_ratio":"16:9",
  "resolution":"720p",
  "image":{"url":"https://example.com/first-frame.png"},
  "reference_images":[{"url":"https://example.com/ref.png"}],
  "reference_audios":[{"voice_id":"eve"}]
}
```

生成时 `duration` 为整数 1–15 秒，缺省为 8；`resolution` 为 `480p|720p|1080p`，缺省为 `720p`；`aspect_ratio` 为 `1:1|16:9|9:16|4:3|3:4|3:2|2:3`，缺省为 `16:9`。使用 `image` 时只能提供 `url` 或 `file_id` 之一；参考模式下 `image` 不能与 `reference_images/reference_audios` 同时使用，且 1080p 会被拒绝。成功响应为 `{"request_id":"..."}`，保存它，不要把任务状态只放在内存中。

### `GET /v1/videos/{request_id}`

响应状态：

```json
{"status":"pending","progress":42}
```

完成：

```json
{"status":"done","progress":100,"video":{"url":"https://...","duration":8}}
```

失败：`{"status":"failed","error":{"code":"...","message":"..."}}`。MVP 每 3 秒轮询，指数退避只用于网络错误；HTTP 4xx 不重试。完成 URL 需支持在线播放、下载和分享。

### 视频媒体读取

- `GET /v1/videos/{request_id}/content`：需要 Bearer Key，适合任务没有归档 asset 时读取；移动端下载时必须附带 Authorization。
- `GET /v1/media/videos/{asset_id}`：公开归档媒体读取，支持浏览器/播放器的 Range 请求；URL 依赖不可猜测 asset ID，应视为可分享链接。
- 图片同理可使用公开 `GET /v1/media/images/{asset_id}`。

### 编辑/延长（P1）

- `POST /v1/videos/edits`：`{model,prompt,video:{url|file_id}}`
- `POST /v1/videos/extensions`：同上，可增加 `duration`；延长时长缺省 6 秒，范围 2–10。编辑不接受 `duration`，编辑/延长都不接受 `aspect_ratio` 或 `resolution`。

## 7. 语音

### `GET /v1/tts/voices?model=<model>`

响应：`{"voices":[{"voice_id":"eve","name":"Eve","language":"en"}]}`。列表为空时允许用户输入/使用服务端默认 voice，但要提示可能不被模型支持。

### `POST /v1/tts`

```json
{"model":"grok-voice-latest","text":"你好","voice_id":"eve","language":"zh","speed":1.0}
```

`text` 和 `language` 必填；`model` 缺省为 `grok-voice-latest`；`speed` 服务端范围为 0.25–4.0，当前创作台 UI 暴露 0.7–1.5。可选 `output_format:{codec,sample_rate,bit_rate}` 和 `with_timestamps`。`Accept` 应为 `application/json, audio/*`。服务端可能返回原始音频字节（通常 `audio/mpeg`），也可能返回 JSON：`{"audio":"<base64>","content_type":"audio/mpeg","duration":1.2}`。客户端均需支持。

### `POST /v1/stt`

使用 `multipart/form-data`，不要手动设置 boundary：

- `model`: 例如 `grok-stt`
- `language`: 可选
- `format`: `true`
- `file`: 音频文件

也可使用 `application/json` 提供公网 `url`，但 APK 本地文件路径必须使用 multipart。自定义 `/v1/stt` 支持 `format`、`diarize`、`keyterm` 等字段；响应至少有 `text`，可含 `language`、`duration`、`words[]`。Android 使用系统文件选择器；上传前限制文件大小和 MIME，超限给出本地提示。

### 其他语音接口（P2）

`POST /v1/audio/speech`、`/v1/audio/tasks`、`POST /v1/audio/transcriptions`、`GET /v1/realtime` 和 `GET /v1/stt` 可作为兼容扩展；后两者是 WebSocket，不纳入 MVP。`/v1/tts/voices/{voice_id}` 也可用于读取单个 voice。

## 8. 客户端错误处理矩阵

| 状态 | 客户端行为 |
|---|---|
| 400 | 显示服务端 message，保留表单内容，不自动重试 |
| 401/403 | 提示 URL/Key 无效或 Key 无权限，提供重新配置入口 |
| 404 | 提示当前公共网关版本不支持该能力 |
| 408/网络超时 | 可重试；聊天显示已生成部分 |
| 429 | 显示限流，读取 Retry-After（若有），延迟后重试 |
| 5xx/503 | 显示服务未就绪或上游失败，视频查询除外按退避重试 |
| 非 JSON/坏 SSE | 显示协议不兼容，记录脱敏诊断信息 |

源码实际 OpenAI 错误对象还包含 `type` 和 `param`：

```json
{"error":{"message":"客户端 API Key 无效","type":"authentication_error","code":"invalid_api_key","param":null}}
```

`429` 的 `type` 为 `rate_limit_error`，`5xx` 的 `type` 为 `server_error`；网关可能同时返回 `Retry-After`。
