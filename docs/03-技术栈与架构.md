# Android APK 技术栈与架构建议

## 1. 推荐方案

推荐 **React/Vite + Capacitor**，而不是从头重写原生界面。原因是上游创作台本身已经是 React 19 + TypeScript + Vite，Markdown 渲染、Responses SSE 解析、聊天会话交互可以复用；Capacitor 只负责 Android 壳和系统能力。

### 核心技术

- UI：React 19、TypeScript、Tailwind CSS；移动端重做布局，不直接照搬桌面侧栏。
- 构建：Vite、Capacitor Android、Gradle。
- 路由：React Router；主路由为连接设置、创作台、历史、设置。
- 服务端状态：TanStack Query；模型目录、voice 列表和视频任务查询使用 query/cache。
- 本地状态：Zustand 或 React Context；会话消息使用结构化 schema 校验。
- 网络：原生 `fetch` + AbortController；SSE 使用 `ReadableStream` 自定义解析器；视频轮询使用 Query；Realtime 以后用 WebSocket。
- 后台任务：视频轮询和下载使用 Android WorkManager/前台服务边界控制；前台页面只负责观察任务状态，不把长任务只放在 React 内存。
- 数据：Capacitor Preferences/DataStore 保存非敏感设置；API Key 用 Android Keystore 封装的安全存储；历史建议加密 SQLite（SQLCipher）或加密 JSON 文件。
- 媒体：Capacitor Filesystem、Share、Media/系统 Intent；音频播放用原生插件或 HTML5 audio 兼容层。
- 测试：Vitest/Testing Library 做协议和状态单测；Playwright 做 Web 壳回归；Detox 或 Maestro 做 Android 关键流程；MockWebServer/WireMock 模拟公共网关。
- CI：GitHub Actions，执行 TypeScript 检查、lint、单测、Android assembleDebug/assembleRelease；发布签名只使用 CI Secret。

## 2. 分层

```text
UI Layer
  ConnectionScreen / CreativeConsole / History / Settings
        |
Feature State Layer
  chatStore / mediaQueries / videoJobStore
        |
Gateway Client Layer
  Grok2ApiClient (baseUrl, auth, timeout, abort, error mapping)
        |
Protocol Layer
  models / responses-sse / images / videos / tts / stt
        |
Platform Layer
  SecureStore / Files / Share / Audio / Network status
```

所有请求必须经过 `Grok2ApiClient`，页面不得直接拼接 URL 或读取 Key。客户端只实现公共 `/healthz`、`/readyz` 和 `/v1/*`；禁止引入 admin API client。

源码复核：`frontend/src/features/creative-console/creative-console-api.ts` 当前使用相对路径 `/v1/...`，而 APK 必须把这些路径改为配置的绝对 Base URL；不能直接复制现有 API 文件后期待 Capacitor 自动代理。

## 3. 配置与隔离

配置对象：

```ts
type ConnectionProfile = {
  id: string;             // 随机 UUID
  baseUrl: string;        // 去尾斜杠，不含 /v1
  apiKeyRef: string;      // Keystore 中的引用，不是明文 Key
  displayName?: string;
  createdAt: number;
};
```

会话 scope 使用 `sha256(normalizedBaseUrl + "\\n" + apiKey)` 的前 16–32 字符；只保存 scope，不保存完整 Key。切换 profile 时清理内存中的 Authorization header、模型缓存、视频查询和未完成请求。

## 4. 关键实现约束

### URL

- 只接受 `https://`；开发构建可配置局域网 HTTP 白名单。
- 去尾 `/`，拒绝包含 `/api/admin` 的地址。
- `new URL()` 校验 host；统一使用 `${baseUrl}/v1/...`。
- 媒体相对 URL 只能解析到同一 Base URL，防止跨站资源误加载；注意公共网关的归档图片/视频公开读取端点不要求 Bearer，应用应把结果 URL 当作可分享资源处理。

### Key

- 使用 Android Keystore 生成/保护加密密钥；不使用普通 localStorage 保存 Key。
- 禁止日志、埋点、剪贴板、Intent extras、崩溃报告记录 Authorization。
- “显示 Key”必须是一次性受系统认证保护的操作；清除连接时同步删除 Key 和可选历史。
- 默认关闭 Android 自动备份中的敏感数据。

### SSE

- 逐 chunk 解码，保留跨 chunk 的 UTF-8 和事件缓冲。
- 支持 `data:` 多行拼接、空行分隔、`[DONE]`、未知事件忽略。
- 用 request sequence 防止旧流写入新会话；Abort 后不把取消当成失败。
- 后台超过超时时间时停止流并提示用户重试，不在后台无限保持连接。

### Markdown

使用 marked 或等价解析器后做白名单清洗：链接仅允许 `https/http/mailto`；图片仅允许 HTTPS 或当前网关 `/v1/media/images/`；禁止脚本、内联事件和任意 HTML。

### 视频

任务写入本地数据库后再开始轮询；轮询任务要有最大存活时间和取消入口。公网 URL 不下载到客户端再上传，直接交给公共网关；本地文件上传必须等服务端提供公共临时上传协议。

## 6. 版本与发布策略

- 先锁定公共网关版本和接口快照，再开发 APK。
- `GET /v1/models` 能力元数据若采用服务端增强，必须保留旧字段并增加版本兼容测试。
- Debug 包允许测试 HTTP；Release 包强制 HTTPS、关闭调试日志和 WebView 调试。
- 发布前做真机弱网、旋转、后台、横屏平板、低存储、中文/英文、深色主题测试。

## 7. 不推荐的方案

- 不建议把完整管理端 Web 页面直接套进 WebView：它依赖 admin 登录和相对 `/v1` 地址，且 Key 暴露面更大。
- 不建议 Flutter/纯 Kotlin 作为第一版：会重写现有 SSE、Markdown、媒体和会话细节，交付风险更高；若后续要 iOS/高性能原生体验，再评估迁移。
