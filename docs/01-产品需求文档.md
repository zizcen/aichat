# Grok2API 创作工作台 Android APK 产品需求文档

## 1. 文档目的

本文档是后续开发的产品基线。目标是把 grok2api 管理端中的“创作控制台”做成独立 Android APK；用户只需填写已经部署在 VPS 上的 grok2api 服务地址和客户端 API Key，即可使用聊天、图片、视频和语音能力。

调研基线：`chenyme/grok2api` `main`，本地源码版本 `v3.1.4`，调研日期 2026-08-24。上游项目持续变化，开发开始前应重新确认公共 API 和模型能力。

## 2. 产品边界

### 2.1 做什么

- 首次启动引导用户填写 Base URL 和 API Key，并测试连接。
- 通过公共 `GET /v1/models` 获取当前 Key 可用的模型；允许手动输入模型 ID 作为兜底。
- 提供与原创作台相近的四个工作区：聊天、图片、视频、语音。
- 本地保存会话、偏好和生成结果索引；媒体可预览、保存、分享。
- 所有推理请求直接发送到用户配置的 grok2api，不增加自有中转服务。

源码核对：当前管理端创作台本身通过 `/api/admin/v1/client-keys`、`/api/admin/v1/models` 和 `/api/admin/v1/media/inputs/*` 获取密钥、能力元数据和临时媒体文件；这些调用只属于管理端，APK 必须替换为公共接口和本地安全存储。

### 2.2 明确不做

- 不做 Grok 登录、OAuth/SSO、账号池、代理池、Cloudflare、上游重试和转发。
- 不做 grok2api 管理后台：管理员登录、账户管理、模型路由、Client Key 创建、审计、运行设置。
- 不依赖 `/api/admin/v1/*`。APK 只有用户输入的 Base URL 和 API Key。
- 不把 API Key 上传到第三方服务器，不嵌入开发者自己的 Key。

## 3. 用户与核心流程

### 3.1 首次连接

1. 用户输入 `https://example.com` 和 `g2a_xxx`。
2. 客户端规范化 URL：去掉末尾 `/`，禁止路径重复拼接；最终公共 API 根地址为 `{baseUrl}/v1`。
3. 调用 `GET /healthz`、`GET /readyz` 和带 Bearer 的 `GET /v1/models`。
4. 成功后进入创作台，保存配置到 Android Keystore 保护的本地存储。
5. 失败按 401/403、网络/TLS、服务未就绪、Key 无模型权限分别提示。

### 3.2 聊天

- 新建、切换、重命名、清空、删除会话；最多保存 50 个会话。
- 支持 Markdown、代码块复制、思考内容折叠、工具活动展示。
- Enter 发送，Shift+Enter 换行；流式生成时支持停止，保留已生成内容。
- 用户消息支持编辑并从该消息重新生成；助手消息支持重试和本地编辑。
- 支持 `auto/none/low/medium/high/xhigh` 推理选项；支持 Web Search/X Search 开关，但只有服务端/模型支持时才展示或启用。
- 切换 Base URL 或 API Key 后，模型、会话和缓存必须隔离。

### 3.3 图片

- 输入提示词，生成 1–4 张图片。
- 支持服务端返回的宽高比、1k/2k 分辨率；`quality` 仅在模型能力允许时显示。
- 结果网格预览，点击查看大图，保存到系统相册，分享和重试。
- 首版至少实现生成；图片编辑作为 P1，需确认公共 `/v1/images/edits` 在目标部署启用。

### 3.4 视频

- 首版实现文本生成、任务进度、完成预览、保存/分享、失败重试。
- 请求异步返回 `request_id`，客户端轮询 `GET /v1/videos/{request_id}`；默认每 3 秒一次，前后台切换时暂停并恢复。
- 支持提示词、时长、比例、分辨率和公网首帧/参考图 URL。
- 视频编辑/延长作为 P1。
- 本地视频/图片上传暂不纳入 MVP：当前创作台上传依赖 admin staging 接口，客户端只有公共 Key 无法调用。若必须支持，需先在 grok2api 增加受 Client Key 保护的临时上传接口。
- 公网图片/视频 URL 可以直接传给公共视频接口；“暂不支持本地文件”指 APK 不应调用管理端 staging，也不等于禁止公网 URL。

### 3.5 语音

- TTS：选择模型、声音、语言和语速，生成音频，播放、下载、分享。
- STT：从系统文件选择器选音频，上传并展示文本、语言、时长和可选词级时间戳。
- MVP 使用系统文件选择，不默认申请录音权限；录音作为 P1，需增加隐私说明和 `RECORD_AUDIO` 权限。
- Realtime WebSocket 语音作为 P2，单独评估后台、蓝牙和网络恢复。

### 3.6 原作台控件基线

以下是源码中当前创作台的默认值和 UI 范围，APK 做“界面差不多”时应优先保持一致；这是 UI 范围，不等于服务端所有可接受值：

- 图片：数量 1/2/3/4；比例 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`；分辨率 `1k/2k`；只有模型 ID 以 `grok-imagine-image-2.0` 结尾时显示 `low/medium` 质量选项。
- 视频生成：时长 6/10/15 秒；比例同上七项；分辨率 `480p/720p/1080p`，有参考图或参考音色时隐藏 1080p；视频延长时长 2/4/6/8/10 秒。
- 语音：默认 TTS、语言 `zh`、voice `eve`、速度 `1.0`；语言选项为 `auto/zh/en/ja/ko/fr/de/es`，速度 UI 范围为 0.7–1.5。
- 聊天：默认推理 `auto`，Web Search/X Search 默认关闭，Responses 请求固定 `stream:true` 和 `store:false`；历史最多 50 个会话、约 4 MiB。

## 4. 模型能力适配决策

公共 `GET /v1/models` 当前返回 OpenAI 风格的 `id/object/created/owned_by`，不返回管理端使用的 `provider/capability`。因此 APK 不能仅凭该响应可靠判断某模型是聊天、图片、视频还是语音。

开发前必须选择并记录一种方案：

1. **推荐：服务端增强**：在 grok2api 公共模型响应增加可选 `capability` 或 `supports` 字段，保持旧客户端兼容。
2. **无服务端改动**：APK 内置已知模型能力映射，同时允许手动输入模型；未知模型通过实际 endpoint 探测，结果缓存并允许用户覆盖。

在方案确定前，不得把模型按 capability 自动分组作为硬编码前提。

## 5. 非功能需求

- Android 8.0（API 26）及以上；手机优先，平板自适应；深色主题优先匹配截图。
- 所有生产请求必须 HTTPS；HTTP 仅允许开发构建或用户明确开启的局域网调试模式。
- API Key 不出现在日志、崩溃报告、剪贴板、会话标题、截图和分析事件中。
- 网络请求可取消；超时、断网、401/403、429、5xx、非 JSON 和 SSE 异常均有可操作提示。
- 键盘弹出时输入框不遮挡；旋转、进后台、恢复网络后不丢失已生成内容。
- Markdown 和远程媒体 URL 必须安全渲染，仅允许 `https` 或当前网关媒体路径。
- grok2api 的 `/v1/media/images/{asset_id}` 和 `/v1/media/videos/{asset_id}` 是公开读取端点（依靠不可猜测的资源 ID），APK 应把生成结果 URL 当作可分享数据，不写入日志或诊断信息。

## 6. MVP 验收标准

- 新安装 APK 能在 2 分钟内完成 URL/Key 配置并看到可用模型。
- 聊天能逐 token 展示文本，能停止、重试、恢复历史；同一 Key 下重新打开应用内容不丢失。
- 图片生成能正确处理 URL 和 `b64_json` 两种数据项。
- 视频能完成 `pending -> done/failed` 状态闭环并播放结果。
- TTS 能处理二进制音频和 JSON+Base64；STT 能发送 multipart 文件并展示文本。
- 切换 URL/Key 后旧会话不可误发到新服务。
- API Key 清除后，本地安全存储、会话索引和媒体引用按用户选择删除。

当前源码还将聊天历史限制为最多 50 个会话、约 4 MiB；APK 可以沿用该上限，但应在达到容量时给出提示，而不是静默丢弃用户内容。
