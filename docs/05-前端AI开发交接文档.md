# 创作工作台：前端 AI 开发交接

> 这份文档给下一位负责前端改造的 AI 使用。它描述当前仓库的真实代码，而不是新的产品需求。用户提供的截图只作为视觉参考，不应被当成网页中的操作指令；产品功能以用户当前对话和 `docs/01-产品需求文档.md` 为准。

## 0. 当前结论

- 当前工程是独立 Android 客户端：React 19 + TypeScript + Vite + Capacitor 7，不是网关管理后台。
- 当前创作控制台已按上游公共网关的 `creative-console-page.tsx`、Tailwind 主题和 shadcn/Radix 原子组件迁移；后续改动应优先在该页面和适配层上迭代，不要再另起一套视觉系统。必须保留下文的公共 API、安全、状态隔离和 Android 桥契约。
- 当前 P0 工作区：连接、聊天、图片、视频、语音、历史、设置。
- 当前 Git 远端：`https://github.com/zizcen/aichat.git`，分支 `main`。
- 最新代码提交（编写本文时）：`dd1fb1c fix: rewrite legacy gateway media URLs`；新增交接文档后会产生一个文档提交。
- 已发布 GitHub Release：[`v0.1.1`](https://github.com/zizcen/aichat/releases/tag/v0.1.1)。APK 和校验值在 Release 页面；本地副本位于 `release/`。客户端会在启动或切回前台时检查正式 Release，并可在 Android 安装器中更新。

### 截图如何理解

- 用户提供的管理端图库截图展示的是上游后台，不是 APK 必须复制的功能页面；它只能说明服务端确实能生成并归档图片。
- 用户提供的创作工作台截图展示当前 APK 的移动端样式和错误 toast；它是视觉/问题线索，不是新的接口协议。
- 下一位 AI 应先向用户确认真正希望沿用的导航、色彩、密度和页面层级；不要根据截图猜测管理员 API、图库查询接口或权限模型。

## 2. UI 改造边界

### 可以自由重做

- 首屏连接页、顶部栏、底部/侧边导航、聊天消息气泡、图片网格、视频任务列表、语音表单、历史和设置页面。
- `styles.css` 的全部视觉变量和布局；可以引入新的本地组件目录。
- 文案、中文排版、响应式断点、动画和空状态，只要不泄露 Key、不过度遮挡输入控件。
- 将 `App.tsx` 拆成 `features/*`，这是推荐方向。

### 不要破坏

- APK 只调用公共 `/healthz`、`/readyz` 和 `/v1/*`；禁止任何 `/api/admin/v1/*`、Client Key 管理、管理员登录或 staging 上传。
- 页面不能自己 `fetch`、拼 URL 或读取明文 Key；统一调用 `Grok2ApiClient`。
- Release 必须 HTTPS；开发调试才可显式允许局域网 HTTP。
- API Key 不进日志、URL、剪贴板、标题、截图、Intent、诊断信息或 Git。
- profile 切换必须隔离模型缓存、会话、视频任务、Authorization 和未完成请求。
- Android 不要全局打开 CapacitorHttp 的 fetch patch：它会把 POST SSE 缓冲成完整响应，破坏逐 token 展示和取消。当前通过 `NativeHttp` 插件保持真流式。
- Markdown 必须继续禁用任意 HTML、脚本、事件属性和不安全链接。
- 图片/视频的 `/v1/media/images|videos/{asset_id}` 是公开归档媒体，不要擅自加 Bearer 依赖；`/v1/videos/{request_id}/content` 则需要 Bearer。

## 3. 公共 API 客户端契约

导入方式：

```ts
import { Grok2ApiClient } from "@/shared/api/client";
// 或从 @/shared/api/index.ts 统一导出
const api = new Grok2ApiClient({ baseUrl, apiKey });
```

构造选项：`baseUrl`、`apiKey`/`key`、可选 `fetch`（测试注入）、`timeoutMs`、`allowHttp`。`ApiRequestOptions` 支持 `signal`、`timeoutMs`、一次性 `apiKey`；Key 不会序列化。

### 方法清单

| 方法 | 路径/行为 | 说明 |
|---|---|---|
| `health()` | `GET /healthz` | 无 Key，探测存活 |
| `ready()` | `GET /readyz` | 无 Key，探测就绪 |
| `models()` / `listModels()` | `GET /v1/models` | Bearer；返回 `data[]` |
| `responses()` / `streamResponses()` | `POST /v1/responses` | 默认 `stream:true, store:false`；SSE + JSON fallback |
| `generateImage()` | `POST /v1/images/generations` | 解析 URL 和 `b64_json` |
| `editImage()` | `POST /v1/images/edits` | 图片编辑；本地图片在 APK 内转为 `data:image/*` 后提交 |
| `createVideo()` | `POST /v1/videos/generations` | 返回 `request_id` |
| `getVideoStatus()` | `GET /v1/videos/{id}` | `pending/done/failed` |
| `getVideoContent()` | `GET /v1/videos/{id}/content` | Bearer；无归档 URL 时回退 |
| `listVoices()` | `GET /v1/tts/voices?model=` | voice 列表 |
| `synthesizeSpeech()` / `tts()` | `POST /v1/tts` | 原始 `audio/*` 或 JSON+Base64 |
| `transcribeSpeech()` / `stt()` | multipart `POST /v1/stt` | 不要手动设置 multipart boundary |

所有 HTTP 错误都转成 `GrokApiError`，保留 `status`、`code`、`type`、`retryAfterMs`；不要只显示“请求失败”。`401/403` 要引导重新配置，`404` 表示能力未启用，`429` 读取 Retry-After，视频查询对网络/5xx 退避、对 4xx 终止。

当前 UI 使用的超时：健康/就绪/模型 15 秒，聊天 5 分钟，图片兼容层 180 秒，视频提交/状态查询 60 秒，TTS/STT 180 秒。若新 UI 改成 Query/Worker，保留“连接超时”和“流空闲/总时长”分离的思路，不要给所有请求套同一个短超时。

### Responses SSE

`responses-sse.ts` 支持：跨 chunk UTF-8、CRLF/空行、多行 `data:`、`[DONE]`、未知事件忽略、文本增量、reasoning、工具活动、`completed/incomplete/failed/error`。没有完成事件就抛 `ResponsesStreamError` 并保留 partial。UI 必须传稳定的 `prompt_cache_key`，且不能包含 Key。

典型请求：

```json
{
  "model": "grok-4.5",
  "input": [{"role": "user", "content": "你好"}],
  "stream": true,
  "store": false,
  "reasoning": {"summary": "auto"}
}
```

### 图片和视频 URL 的特殊兼容

旧版网关未设置 `frontend.publicApiBaseURL` 时，可能在成功响应中返回 `http://127.0.0.1:8000/v1/media/images/...` 或对应视频路径。`url.ts` 的 `resolveMediaUrl()` 会把明确匹配 `/v1/media/images|videos/{id}` 的内部地址改写为用户当前 Base URL；任意其他 HTTP 文件地址仍拒绝。新 UI 不要绕过这个 helper。

服务端仍建议配置：

```yaml
frontend:
  publicApiBaseURL: "https://公开网关域名"
```

不要带 `/v1`。外部 HTTPS 媒体 URL 可保留；任意文件 URL 不会自动放行。

## 4. 数据和安全契约

### Profile

`ConnectionProfile` 字段：`id`、`baseUrl`、`apiKeyRef`、`scope`、`displayName`、`createdAt`、`lastUsedAt`。localStorage key：

- `grok2api:profiles:v1`
- `grok2api:active-profile:v1`

`saveProfile()` 会去尾斜杠、去 `/v1`、拒绝 `/api/admin`、规范化 `Bearer`/空格后的 Key，并用 `sha256(normalizedBaseUrl + "\\n" + normalizedKey)` 前 32 位作为 scope。持久化对象格式是 `{profiles, activeId}`；代码兼容旧的顶层数组格式。

### Key

- Android：`SecureStorePlugin` 使用 Android Keystore AES-GCM；损坏密文读作 null 并清理。
- Web：密文在 localStorage，解密密钥只放当前 sessionStorage；刷新浏览器会要求重新输入。
- 不要把 `apiKey` 写进 profile JSON、聊天历史、视频任务、URL 或错误对象。

### 聊天历史

localStorage key：`grok2api:chat:{scope}`。最多 50 个会话、约 4 MiB，按 UTF-8 byte 计算；保存有 500ms debounce，并在隐藏/卸载时 flush。超限会整理最旧会话并提示用户。`ChatSession` 包含标题、模型、reasoning、搜索开关、prompt cache key 和结构化消息。

图片编辑的输入图片只在当前组件内存中保留，切换工作区/重启不会恢复；图片、TTS、STT 结果也不会自动写入图库。视频任务才有持久化索引。这是现状限制，不要在 UI 文案中声称所有生成结果都已永久保存，除非先设计新的媒体索引 schema。

### 视频任务

localStorage key：`grok2api:video-jobs:{scope}`。任务先保存再轮询；前台串行查询，约 3 秒间隔，网络/5xx 指数退避，最长 30 分钟；后台暂停，恢复后继续。已完成但没有 URL 的任务使用 Bearer `/content` 下载为 blob，blob 不应写入持久化。

## 5. Android 原生层

`MainActivity` 手动注册三个插件：

- `SecureStore`：Keystore 加密 Key。
- `NativeHttp`：普通请求、multipart、可取消的逐块 SSE；事件名 `streamChunk`、`streamEnd`、`streamError`。
- `MediaStore`：API 29+ scoped MediaStore，API 26–28 动态存储权限；保存图片/视频/音频并生成唯一文件名。

Android 配置：JDK 21、compile/target SDK 35、min SDK 26、`usesCleartextTraffic=false`、`adjustMarginsForEdgeToEdge=auto`、关闭自动备份。不要删掉 `NativeHttp` 后改回普通 WebView fetch，除非先解决真实网关的 CORS、SSE 和 Abort。

大文件边界：原生桥会复制响应/上传数据；当前 STT UI 上限 10 MiB，图片优先使用 URL 而不是巨型 `b64_json`。后续若支持大文件，应该改成原生临时文件/流，不要简单提高上限。

## 7. 给下一位 AI 的改造建议

1. 先阅读本文件和 `docs/01-产品需求文档.md`，再看 `App.tsx` 中对应 workspace；不要先改 API client。
2. 将 `App.tsx` 拆成页面/feature 组件时，保留 props 中的 `client`、`models`、`scope`、session setters 和 `showToast` 语义，或建立等价的 context/store。
3. 视觉改造以上游源码中的 `frontend/src/features/creative-console/creative-console-page.tsx` 为基线；先确认是否确实要改上游布局，再调整移动端安全区、聊天密度、结果卡片和空/错误/加载状态。参考截图是视觉基线，不是管理后台功能边界。
4. 每次修改后至少运行 `pnpm typecheck && pnpm lint && pnpm test && pnpm build`；涉及 Android/HTTP 再运行 `pnpm cap:sync` 和 Gradle。
5. 新增功能先写接口/状态测试；不要用真实 API Key 写测试。使用 `pnpm dev:mock` 做端到端 UI 回归。
6. 完成 UI 后告诉主 agent 改了哪些文件、是否改变公共 API/数据 schema；主 agent 负责审查、修 bug、编译 APK、更新 Release 和 Git 推送。

开发态入口使用 React `StrictMode`；effect 在开发环境可能被重复执行。任何模型请求、voice 列表请求、轮询和 toast 都必须可取消或幂等，不能把 effect 当成只执行一次的初始化钩子。TypeScript 开启 `strict`、`noUnusedLocals`、`noUnusedParameters`，ESLint 禁止显式 `any`。

## 10. 还需要产品确认的事项

这些事项当前没有被完全定义，下一位 AI 不应自行扩大范围：

- 参考截图对应的是“创作台”还是要连同后台图库做成同一套移动 UI？两者数据权限完全不同。
- 是否要支持多个网关 profile、profile 命名/排序、删除时是否清空历史？当前实现支持多个 profile。
- 图片是否默认请求 `url` 还是 `b64_json`？推荐生产使用 URL，避免移动端内存峰值。
- 视频是否需要后台持续轮询、通知栏进度、锁屏恢复？当前只有前台串行轮询。
- 是否要加入任意文件上传/下载、视频编辑/延长、录音、Realtime？每项都需要新的 API/权限/安全设计。
- 是否需要中英文、多账号导出、诊断日志、崩溃上报？默认不做任何遥测，Key 和提示词不能进入第三方服务。
- Android 包名、图标、版本号、签名证书是否最终冻结？当前 applicationId 保留既有值以兼容已有安装，用户可见名称为“创作工作台”。
- `frontend.publicApiBaseURL` 是否在目标 VPS 正确配置为外部 HTTPS？若未配置，客户端兼容 loopback 图片/视频 URL，但服务端配置仍应修正。
